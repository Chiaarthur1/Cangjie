## 1. Три бага, которые блокировали «172 черты»

### Баг 1. Композер не умел собирать вложенные поддеревья

`cangjie_composer._can_compose()` проверял, можно ли нарисовать ЭЛЕМЕНТ.
Но рекурсия передавала туда **поддерево IDS** — строку вроде `⿰龍龍`
(внутри `⿱龍⿰龍龍` = 龘), а не одиночный знак.

Дальше код искал `⿰龍龍` в скелетах MakeMeAHanzi и в корпусе CHISE:
```python
if self.repo.get_medians(char):   # '⿰龍龍' -> пусто
    return True
ids = self.ids_corpus.get(char)    # '⿰龍龍' -> None
if not ids:
    return False
```
Поддерево не является символом → проверка падала → `False`.

**Симптом (замаскированный):** `鱻` (⿱魚⿰魚魚) «собирался», а `龘`
(⿱龍⿰龍龍) — нет. Разница в том, что у `鱻` есть готовый скелет
MakeMeAHanzi (33 медианы) — рекурсия до поддерева не доходила.
`龘` (48 черт) скелета не имеет, поэтому честно проверял структуру и падал.

**Исправлено:** добавлена ветка «это поддерево, а не одиночный знак» —
разбираем как IDS и проверяем потомков.

**Проверка после фикса:**
| Знак | Черт | Было | Стало |
|---|---|---|---|
| 龘 (⿱龍⿰龍龍) | 48 | ✗ | ✓ |
| 𰻞 (биан) | 58 | ✗ | ✓ |
| 𰻝 | 64 | ✗ | ✓ |
| 𡧃 | — | ✗ | ✓ |
| 𬢕 | — | ✗ | ✓ |

### Баг 2. Геометрия операторов окружения была неверной

Операторы `⿴⿵⿶⿷⿸⿹⿺⿻⿼⿽` означают «внешний элемент ОБТЕКАЕТ внутренний».
Код рисовал внешний элемент на **всё поле**, а внутренний — в центральном
квадрате, причём **обрезал** его по границам рамки.

Для `⿺` (辶/廴 обтекает) это давало полную кашу: 辶 занимал 100% площади,
а содержимое терялось.

**Масштаб проблемы** — операторы окружения стоят в **12 432 знаках** корпуса
(13% датасета), `⿸` — 4158 знаков, `⿺` — 3699.

**Исправлено:**
- введена `_enclosure_zones()` — своя зона внешнего элемента для каждого
  из 10 операторов (⿴ со всех сторон, ⿵ сверху, ⿺ снизу-слева и т.д.);
- оба элемента теперь **масштабируются** в свои зоны, а не обрезаются.

**Проверка (визуально):** 道, 這, 進, 遠, 過, 國, 廟 — 辶 обтекает
содержимое, а не заливает поле. Скриншот: `artifacts/enclosure_fixed.png`.

### Баг 3. scipy пропал из окружения → проект не импортировался

Песочница пересоздалась, `pip install scipy` недоступен (индекс pypi
не отвечает). `cangjie_dfine_losses` импортировал
`scipy.optimize.linear_sum_assignment` на верхнем уровне → падали
`cangjie_photo_decoder` и `cangjie_edge_cpu_runtime`.

**Исправлено:** scipy стал необязательным, добавлен венгерский алгоритм
(Jonker–Volgenant) на чистом numpy.

Важная деталь: **первая версия фолбэка была неверной** — паддинг
прямоугольной матрицы до квадрата значением `INF` ломал оптимум
(находил решение ХУЖЕ оптимального). Переписано на корректный
прямоугольный вариант с транспонированием при `n_rows > n_cols`.

**Проверка:** 60 случайных матриц 1×1…7×7, сравнение с полным перебором —
`brute-force agreement: OK`. Раньше на этой же проверке было MISMATCH.

Побочная польза: проект теперь работает **без scipy** — то есть на ноуте
не нужно ставить лишнее.

## 2. Новый модуль `cangjie_fullchar_bank.py` — банк ПОЛНЫХ знаков

### Зачем

Банк `cangjie_paleo_matcher` содержит **4 720 ЛИСТОВЫХ компонентов**
(радикалы, из которых знак складывают). Проверено:

```
bank size (components only): 4720
has 龘 in bank? False | 鱻? False | 龜? True
bank composition: leaf=4720 composite=0
```

**Составных знаков в банке ноль.** То есть опознать по фото знак, который
не является отдельным радикалом, было нечем — а палеографу нужно именно
это («что это за знак»).

### Что сделано

Новый модуль строит **второй** банк — по полным знакам, отдельно для
каждой эры (KAISHU / SHANG_JIAGUWEN / ZHOU_JINWEN / XIAOZHUAN):

- источник: 97 431 знак с IDS-разбором из CHISE (Basic + Ext A…H + Compat);
- рендер: MakeMeAHanzi для знаков со скелетом, рекурсивный композитор
  для остальных (то есть 172-чертные собираются);
- дескрипторы: те же chamfer + HOG, что у component-банка, поэтому
  калибровка и матчер работают без изменений;
- кэш: `.npz` в `data/`, сборка ~25 мин на эру.

**Важно: старый component-банк НЕ тронут.** Новый банк — дополнение.
Если файла нет, система работает ровно как раньше.

## 4. Открытая проблема, которую честно фиксирую

В бенчмарке **KAISHU — самая слабая эра** (0.8533 против 0.96–0.97).
Причина установлена ранее: бенчмарк рендерит кейсы тем же рендерером,
что и банк, поэтому самопроверка идеальна и ничего не проверяет.
Кайшу в реальности — это рукопись и печать с другими пропорциями,
и банк этого не покрывает.

**Честный вывод:** цифры 0.93 — это потолок для СИНТЕТИЧЕСКИХ деградаций.
На живом фото палеографа будет иначе. Нужен либо датасет из музейных
каталогов, либо обучение детектора на реальных съёмках.
