# Project Cangjie — музейный датасет (часть 6)

Дата: 24.10.2026

---

## Зачем

Все честные цифры до сих пор были на **синтетике**: honest eval сам
генерирует деградации тем же рендерером, что и банк. Это потолок
качества, а не реальность. Палеограф работает с **настоящими**
фотографиями костей, бронзы, стел и бамбуковых табличек — и вот
для этого нужен датасет из музейных каталогов.

---

## Что сделано

### Новый модуль `cangjie_museum_dataset.py`

Качает **настоящие** фотографии древних надписей с Wikimedia Commons,
накладывает реальные деградации носителя и пишет манифест с лицензиями
и авторами.

```bash
# сначала посмотреть, что найдётся (ничего не качает)
python3 cangjie_museum_dataset.py --search "oracle bone script" --limit 30 --dry-run

# собрать датасет
python3 cangjie_museum_dataset.py \
    --search "oracle bone script" \
    --search "bronze inscription china" \
    --search "seal script chinese" \
    --search "stele chinese inscription" \
    --limit 60 --out ./data/museum_dataset
```

### Структура выхода

```
data/museum_dataset/
├── manifest.jsonl        — по строке на файл:
│                            id, commons_title, source_page, license,
│                            license_url, artist, date, description,
│                            original_size, variants[]
├── images/<id>.png       — оригинал (обрезанный до 2048 px)
├── images/<id>_BONE.png  — та же кость, но с реальной деградацией
├── images/<id>_BRONZE.png
├── images/<id>_TOPIAN.png
├── images/<id>_PAPER.png
└── LICENSE_SUMMARY.json  — сводка по лицензиям (обязательно при публикации)
```

## Технические грабли (чтобы не наступить)

1. **Wikimedia режет запросы (429).** Нужен нормальный `User-Agent` с
   контактом + пауза между запросами + ретраи с экспоненциальным
   backoff. В коде: `MIN_INTERVAL = 3.0` с для API, `MIN_INTERVAL_DL = 4.0`
   с для картинок (на upload.wikimedia лимит жёстче).
2. **Трекинг-параметры надо убирать** (`?utm_source=...`) — с ними
   действует отдельный, более жёсткий лимит.
3. **Нужен фильтр по теме.** Поиск «stele inscription» выдаёт греческие и
   финикские стелы — для палеографии бесполезно. Добавлен `_is_relevant()`
   с маркерами `_CJK_HINTS` / `_NON_CJK_HINTS`.
4. **Массовую закачку лучше запускать ночью** — лимиты всё равно срабатывают,
   часть файлов не скачается с первого раза (скрипт это переживает:
   повторный запуск докачивает недостающее — скачанные кэшируются).

## Что дальше по датасету

| Шаг | Что нужно |
|---|---|
| 1 | **Разметка боксов компонентов** на музейных фото — сейчас скрипт качает цельные надписи, а для обучения детектора нужны вырезанные иероглифы с разметкой |
| 2 | Массовая закачка (200–500 фото) с ночным запуском |
| 3 | Полуавтоматическая разметка: детектор находит связки → палеограф правит |
| 4 | Обучение детектора на GPU-станции |
| 5 | Честный eval на отложенной части музейного датасета (split по музею, чтобы не переучить) |

**Важно про split:** музейные фото надо делить **по музею/коллекции**, а не
по файлу. Иначе одно и то же письмо попадёт и в train, и в test, и eval
покажет нереальные цифры — ровно та ловушка, что была с первым бенчмарком.

## Связь с главным багом

Найденный ранее баг (рендер шаблонов в 64×64 → слипшиеся штрихи) был
обнаружен именно потому, что я прогнал **реальное фото** через дескодер.
На синтетике он был не виден.

Это подтверждает главный тезис: **синтетика показывает потолок, а не
работоспособность.** Музейный датасет — то, что даст честные цифры.
