Обновленный 16-недельный мастер-план Project Cangjie жестко синхронизирован с нейросимвольным стеком, заменяя устаревшие компоненты на SOTA-решения (RT-DETRv2-X, Qwen2.5-VL) и вводя математический аппарат Logic Tensor Networks. Архитектура распределена между локальной разработкой на Zorin OS и серверными мощностями с 4x RTX 4090 для минимизации простоев. ФАЗА 1: Локальная онтология и анти-галлюцинаторный бенчмарк (Недели 1–3) Где выполняется: Локально (Zorin OS / Windows). Цель: Развернуть графовую базу знаний и подготовить контрольную выборку для тестирования VLM.

* Шаг 1.1: Сборка графа знаний (Neo4j)
  * Разверни локально Neo4j.
  * Импортируй дампы: Unihan, CHISE, «Шовэнь цзецзы» и фонологическую базу Бакстера-Сагара.
  * Сформируй узлы для 214 радикалов Канси. Настрой связи: [:SEMANTIC] для смысловых ключей, [:PHONETIC] для фонетиков (Old/Middle Chinese), и заложи иерархию синтаксических деревьев IDS.
* Шаг 1.2: Подготовка бенчмарка
  * Собери 150 изображений (3 папки по 50 шт.):
    * Dataset\_A: Редкие традиционные знаки (CJK Ext. B-G).
    * Dataset\_B: Древние формы (цзягувэнь, цзиньвэнь).
    * Dataset\_C: Выдуманные, структурно корректные, но несуществующие иероглифы (ключевой тест на отказ VLM).
* Шаг 1.3: Скрипт-верификатор с t-нормой
  * Напиши Python-скрипт оценки, использующий t-норму Лукасевича (\\max(0, x + y - 1)) для жесткого линейного штрафа за несовпадение распознанных ключей с реальной онтологией. ФАЗА 2: Серверная валидация VLM (Неделя 4) Где выполняется: Сервер РТУ МИРЭА (4 \\times RTX 4090, 128 ГБ ОЗУ). Цель: Доказать способность Qwen2.5-VL обрабатывать вертикальный текст и выдавать NULL на выдуманных знаках.
* Шаг 2.1: Деплой Qwen2.5-VL-72B
  * Разверни vLLM с параметром --tensor-parallel-size 4 для распределения весов на все 96 ГБ VRAM (используя QLoRA/INT4 NF4 для оптимизации памяти).
  * Активируй архитектурные фичи Qwen (Patch Merger и 3D M-ROPE) для корректной нативной работы с вертикальным текстом без искажения 2D-топологии.
* Шаг 2.2: Прогон бенчмарка
  * Скорми модели бенчмарк (150 картинок).
  * Системный промпт: «Разложи иероглиф на ключи по IDS и назови значение. Если знак тебе не знаком, выдай только структуру, а в поле "значение" верни NULL».
* Шаг 2.3: Анализ "Linguistic Crutch"
  * Пропусти результаты через скрипт-верификатор. Модель должна дать 100% NULL на Dataset\_C, доказав, что она опирается на визуальные признаки, а не придумывает значения несуществующим знакам. ФАЗА 3: Фабрика данных и обучение CV-детектора RT-DETR (Недели 5–8) Где выполняется: Недели 5-6 локально, Недели 7-8 на сервере. Цель: Заменить YOLO на архитектуру RT-DETRv2-X для корректной локализации вложенных радикалов (где IoU &gt; 0.85).
* Шаг 3.1: Синтетический генератор (Локально)
  * Используя Python (Pillow, FreeType), сгенерируй от 100 000 до 500 000 изображений CJK-шрифтов с аугментацией (шум туши, царапины, фон старой бумаги).
* Шаг 3.2: Авторазметка Direct Set Prediction (Локально)
  * Сгенерируй точные координаты (x, y, w, h) для 214 радикалов и 12 операторов позиционирования (⿰, ⿱, ⿺).
* Шаг 3.3: Тренировка RT-DETRv2-X (Сервер)
  * Запусти обучение на 4 картах через PyTorch DDP (Distributed Data Parallel), что позволит маскировать отсутствие NVLink, используя шину только для All-Reduce градиентов.
  * Гибридный энкодер (AIFI + CCFF) RT-DETR аппаратно разделит ответственность за внешний контур и внутренние мелкие штрихи. Модель сойдется за 1-2 дня. ФАЗА 4: Neuro-Symbolic Интеграция (Недели 9–11) Где выполняется: Написание пайплайна локально, тесты на сервере. Цель: Соединить зрение (RT-DETR), графовую логику (Neo4j) и дедуктивный разум (Qwen).
* Шаг 4.1: Сборка логического моста
  * Картинка проходит через RT-DETR, выдавая массив Bounding Boxes.
  * Скрипт строит пространственное IDS-дерево.
  * GraphRAG-запрос в Neo4j (используя 60–70 ГБ In-Memory кэша сервера) извлекает историческую семантику и валидирует фонетику.
* Шаг 4.2: Внедрение LTN-шлюза
  * Рассчитай семантический центроид (C\_{sem}) алгоритмом EASA (Entropy-Aware Structural Alignment), отдавая вес редким смысловым детерминативам.
  * Сформируй жесткий JSON-контекст. Системный промпт VLM: «Ты палеограф. Опирайся ТОЛЬКО на JSON из графа знаний. Синтезируй гипотезу композиции, учитывая конфликт/синергию стихий. Штрафной множитель обнулит гипотезы, нарушающие исторические правила». ФАЗА 5: Агентная Дуэль (CoVe-RAG+) (Недели 12–14) Где выполняется: Сервер. Цель: Выявление скрытых правил древнекитайской грамматики через контролируемое соревнование нейросетей.
* Шаг 5.1: Агент-Фальсификатор
  * Берет из Neo4j правила сборки и генерирует новые, дико сложные или OOD-иероглифы (Out-Of-Distribution), намеренно нарушая исторические законы (например, ставя фонетик в позицию смыслового ключа).
* Шаг 5.2: Агент-Критик
  * Пытается декомпозировать сгенерированный знак. Применяя штрафной множитель графа \\prod \\mathcal{G}(Rule\_j), Критик моментально бракует гипотезу при нарушении аксиом.
* Шаг 5.3: Прогон «Слепых Зон»
  * Загрузи в пайплайн сканы реальных нерасшифрованных даосских талисманов. Модель начнет генерировать дедуктивные гипотезы на основе чистой логики радикалов. ФАЗА 6: Экспертная Валидация и Упаковка (Недели 15–16) Где выполняется: Локально. Цель: Оформить проект, защитить интеллектуальную собственность и собрать фидбэк профессионалов.
* Шаг 6.1: Автогенерация отчетов (PDF)
  * Напиши пайплайн (ReportLab или Jinja2 + HTML), который верстает результаты: исходное фото \\rightarrow боксы RT-DETR \\rightarrow IDS дерево \\rightarrow выписка Neo4j \\rightarrow итоговая гипотеза.
* Шаг 6.2: Оффлайн-валидация
  * Распечатай самые сложные разборы (включая нерасшифрованные талисманы). Покажи их преподавателям китайского языка для сбора обратной связи там, где машина могла упустить культурный контекст.
* Шаг 6.3: UI и релиз портфолио
  * Создай веб-интерфейс на Streamlit: «Загрузи фото иероглифа \\rightarrow получи научный разбор».
  * Оформи репозиторий. Алгоритмы дедукции и интерфейс можно выложить в Open Source, а веса RT-DETR и дамп графа Neo4j оставь в закрытом доступе для защиты архитектуры.
