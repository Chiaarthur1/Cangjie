Спецификации вашей серверной графстанции РТУ МИРЭА зафиксированы. При подключении по SSH к Ubuntu накладываются четкие аппаратные ограничения, под которые в проекте уже выстроена математика и оркестрация моделей.

### Аппаратный профиль сервера

| Компонент | Спецификация | Ключевая роль в Project Cangjie |
| --- | --- | --- |
| **GPU Кластер** | **4 $\times$ NVIDIA RTX 4090** (по 24 ГБ VRAM, **всего 96 ГБ**) | Фаза 2 (vLLM TP=4), Фаза 3 (DDP), Фаза 5 (4 воркера TP=1) |
| **Интерконнект** | **PCIe 4.0 x16 (БЕЗ NVLink)** | Жесткое ограничение: запрещены частые межкарточные обмены тензорами |
| **CPU** | **32-ядерный AMD Threadripper PRO** (64 потока) | Синтез данных, векторные вычисления L3-кэша, обслуживание воркеров |
| **ОЗУ** | **128 ГБ DDR5** | 52–60 ГБ под Neo4j PageCache, ~68 ГБ под ОС, даталоадеры и кэши |
| **ОС** | **Ubuntu Server (headless, доступ по SSH)** | Фоновые процессы через `tmux`/`systemd`, доступ через SSH-туннели |

### Матрица размещения моделей по Фазам

#### 1. Фаза 2: `Qwen2.5-VL-72B-AWQ` (Тяжелая валидация)

* **Потребление:** Веса AWQ 4-bit занимают **~40.8 ГБ**.
* **Режим запуска:** `vLLM` с флагом `--tensor-parallel-size 4`.
* **Распределение по VRAM:**
* Каждая карта берет **~10.2 ГБ весов**.
* Свободно **~13.8 ГБ VRAM на каждой карте** под KV-кэш и длинные визуальные токены.


* **Защита шины:** Флаги `--enable-chunked-prefill` и `--limit-mm-per-prompt image=2,video=0` предотвращают забивание шины PCIe 4.0 при параллельном префилле.

#### 2. Фаза 3: `RT-DETRv2-X` (Обучение детектора)

* **Размер:** 67.8M параметров, веса занимают всего **~136 МБ** (BF16/FP16).
* **Режим запуска:** **PyTorch DDP (Distributed Data Parallel)** на 4 процесса.
* **Почему работает без NVLink:** DDP пересылает по PCIe 4.0 только градиенты через `All-Reduce` в конце батча. Объем градиентов (~136 МБ) ничтожен для шины PCIe 4.0 (пропускная способность ~31.5 ГБ/с на слот). Блокировок не будет.
* **Батч:** 64 суммарно (по 16 на карту), `imgsz=640`, `amp=True`.

#### 3. Фаза 4: `SigLIP-So400M` + `Neo4j` (Векторный мост)

* **SigLIP:** Занимает **~1.6 ГБ VRAM** (или может крутиться на Threadripper CPU). Извлекает 1536-мерные эмбеддинги.
* **Neo4j:** Занимает 52–60 ГБ DDR5. Бинарная квантизация (Rescored Binary Quantization) оптимизирована под огромный **L3-кэш Threadripper PRO** для миллисекундного семантического центроида (EASA).

#### 4. Фаза 5: Агентная Дуэль `CoVe-RAG+` (Децентрализованные воркеры)

* **Изоляция шины (TP=1):** Кластер переводится из TP=4 в режим **4 независимых параллельных воркеров** (на каждую RTX 4090 садится отдельный воркер):
* 1 GPU = `Qwen2.5-VL-7B-Instruct` (~14 ГБ VRAM) + инференс `RT-DETRv2-X` (~1.5 ГБ VRAM).
* 32 ядра Threadripper выделяют ровно по 8 ядер на каждого воркера.
* **Межкартный трафик = 0**. Мультиагентная дуэль (Forger vs Critic) работает на полной скорости без ожидания синхронизации.

### Подготовка к SSH-сессии

Для комфортной работы с ноутбука по SSH вам понадобятся:

1. **Проброс портов (SSH Tunneling):**
При подключении к серверу пробрасывайте порты Neo4j, vLLM и Streamlit на свой локальный браузер:
```bash
ssh -L 7474:localhost:7474 -L 7687:localhost:7687 -L 8000:localhost:8000 -L 8501:localhost:8501 user@server_ip

```


* `7474` — Neo4j Browser (визуальный граф прямо в браузере ноутбука на `http://localhost:7474`).
* `8000` — API vLLM (`http://localhost:8000/v1`).
* `8501` — Streamlit UI демо (Фаза 6).


2. **Работа в фоновых терминалах (`tmux`):**
Все длинные процессы (обучение RT-DETR, подъем vLLM-сервера, импорт графа) запускайте внутри `tmux`, чтобы обрыв Wi-Fi на ноутбуке не прерывал вычисления:
```bash
tmux new -s train_rtdetr
# выход из сессии: Ctrl+B затем D
# возврат: tmux attach -t train_rtdetr

```



Контекст аппаратных ограничений и архитектурного стека полностью синхронизирован.
